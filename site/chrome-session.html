Your coding agent can work with the page you already have open, including a signed-in dashboard or a local development page.

codex-ui is a free, MIT-licensed local CLI. It combines screenshots, macOS Accessibility controls, and Chrome DOM inspection. Native desktop control requires macOS 13+.

A real native action.

Recording details and artifact hashes. The command used in the recording:

codex-ui press --chrome-url '?demo=chrome-session' \
  --role button --name 'Mark reviewed' --capture-after

Open the same public example in Chrome to try it. This recording shows an actual desktop operation; the interactive example itself reports only browser state. First-run setup and permissions.

Give your agent the task.

Replace [page URL] with a page you want inspected. Paste this into a local agent that can run commands and view images:

Use codex-ui to inspect [page URL] in my existing Chrome session. If setup is needed, read https://ensomniac.github.io/codex-ui/start.md. Resolve the exact tab, capture and inspect the visible page, then read the relevant live DOM. Report up to three useful findings with screenshots and page evidence. Keep this task to inspection, and tell me what you could not verify.

The CLI also ships a control-local-ui skill for agents. Run codex-ui skill install for Codex, or codex-ui skill install --agent claude for Claude. Other local agents can use the command schema.

Inspect a tab yourself.

Install through the setup guide, run codex-ui doctor, and open the intended page in Chrome. Replace example.com/dashboard with a distinctive literal part of its URL.

1. Capture what is visible

codex-ui capture --chrome-url 'example.com/dashboard' \
  --focus --label dashboard-before

Open the returned capture.path and inspect the image. The neighboring JSON sidecar records the actual screen rectangle and Retina scale. Keep the window visible and unobscured.

2. Read the live page structure

codex-ui chrome-dom --chrome-url 'example.com/dashboard' \
  --selector 'main' --depth 2 --node-limit 80
codex-ui chrome-console --chrome-url 'example.com/dashboard' \
  --level error

Choose a selector present on your page. DOM output includes visible text, attributes and rectangles. Console output reflects the entries exposed by DevTools and its current filters. An unreadable or empty result does not establish that the page has no errors.

3. Connect the findings to the page

Check that the returned URL, title and visible controls belong to the intended tab. Describe the observed problem and its location. If you later authorize a change, repeat the capture and relevant inspection to check its effect.

A URL selector can also match a file:// page. If several tabs match, narrow the URL fragment or use an explicit --occurrence. The CLI reports ambiguity instead of choosing a window for you.

Use it where the current session matters.

codex-ui fits inspection of a dashboard you are already signed in to, visual verification of a local UI fix, and tasks that cross between Chrome and native Mac windows. Browser tests remain useful for repeatable checks in a test-controlled browser.

Chrome inspection temporarily uses the current tab’s DevTools surface, then restores its layout and clipboard. It does not require relaunching Chrome with a debugging port or enabling JavaScript from Apple Events.

Desktop operations run locally without tool telemetry or a hosted account. Your agent host controls how it handles screenshots and command output. Review those artifacts before sharing them.
