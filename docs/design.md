# Visual and editorial system

codex-ui is a desktop tool. Show the interface, explain the behavior, and make the next action obvious.

## Identity

The mark combines a window frame and a pointer. `site/icon.svg` is the canonical square asset; `site/wordmark.svg` is the repository lockup. Keep its proportions and clear space. The mark is independent of Apple and OpenAI.

Use near-black text on white or cool light gray. Blue identifies actions and links. Green is reserved for a confirmed successful state. Avoid decorative terminal syntax in prose, floating badges, ornamental arrows and text over atmospheric gradients.

## Typography and layout

Use the operating system's sans-serif typeface. Monospace belongs to commands, paths and returned data. Body copy is 17px; supporting prose is at least 13px, with 12px labels in compact example controls. Use a small set of type sizes and generous line spacing. Wide pages have a bounded reading width; narrow pages reflow rather than shrink.

The interface should work before JavaScript loads. Native links, details elements, readable code and semantic headings are the base layer. Enhance with copy buttons and tabs. Keep visible keyboard focus, meaningful status announcements and reduced-motion support. Do not hide critical content behind animation.

## Human copy

Use concrete nouns and ordinary verbs. State what the tool does, where it works and what the reader needs. A heading should help someone find information. Avoid repeated slogans, performative confidence, adversarial permission language, and promises that the implementation cannot establish.

Ryan's words are part of the project's history. Preserve exact quotations and attribution. Explain their practical meaning once; do not turn every section into a manifesto. Agents remain explicitly welcome to maintain the project.

## Demonstrations and evidence

A browser example reports browser state. It must not fabricate native-controller output, elapsed times, pointer restoration, or a successful external operation. Show the exact command that can operate the example. Keep interactive controls named and stable so agents can use the same page as humans.

Validate changes in the rendered page, including small screens, keyboard navigation, no JavaScript and reduced motion. Inspect actual screenshots before claiming visual verification.
